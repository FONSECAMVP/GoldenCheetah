## A3.2 — Property-based / fuzz

REQ-002 has three string inputs (email, password, tokenstore_path) and one boolean-ish output channel (login() returns identity dict OR raises). Two testable properties:

- **Forwarding invariant**: for any `(email, password, tokenstore_path)`, the underlying `_gc.Garmin` is constructed with the same triple in the same positional order. Already covered by the happy-path `captured["called_with"]` assertion at one example — universally true for the adapter since it has no branching on input. **Accept-with-rationale**: the adapter is a pure forwarder; an example test plus the mutation pass (M3/M4 killed) is sufficient. A hypothesis-driven property test adds no kill power over the example test.
- **Result-or-raise dichotomy**: `login()` never returns `None` and never returns a partially-populated dict. Covered structurally by the explicit `return {...}` after a successful try-block (no other return paths). **Accept-with-rationale**: enforced by control flow, not test coverage.

No fix-now items. **Defer-with-ticket**: evaluate `hypothesis` for the adapter once the surface widens past REQ-002 (REQ-014 error mapping has ≥6 inputs and is a much better fit). Target: A3/REQ-014 cycle.

## A3.3 — Negative-path

Covered (each test cited):
- Library raises `GarminConnectAuthenticationError("...")` → `GarminError(kind='auth')` with retained `.original` — `test_login_bad_credentials_raises_GarminError_kind_auth`.
- Library raises a non-auth exception → propagates unchanged, NOT reclassified as `auth` — `test_non_auth_exception_is_not_misclassified_as_auth` (M6 killer).
- Library auth exception with empty message → adapter substitutes a non-empty UI-displayable message — `test_auth_error_with_empty_message_still_yields_displayable_message` (M11 killer).
- Failed auth must not leave a token file on disk — asserted inside `test_login_bad_credentials_raises_GarminError_kind_auth`.

Considered and rejected:
- Library raises during `__init__` (e.g., curl_cffi can't initialize TLS). **Accept-with-rationale**: tests would have to fake `_gc.Garmin` itself to throw at construction, which exercises the library's contract not the adapter's. The `_gc is None` guard already covers "library missing" — the test coverage shows it via M1.
- `tokenstore_path` is a directory not a file path. Library's contract; the adapter doesn't inspect the path. Out of scope for REQ-002.

No fix-now items remaining.

## A3.4 — Boundary sweep

REQ-002's inputs are three strings. Boundaries:

| Input | Empty `""` | Very-long (10kB+) | Notes |
|---|---|---|---|
| `email` | Forwarded as-is to library | Forwarded as-is | Adapter never validates; library's `.email` shape is the library's contract. |
| `password` | Forwarded as-is | Forwarded as-is | Same. |
| `tokenstore_path` | Forwarded as-is | Forwarded as-is | Filesystem path validity is the library + OS contract. |

**Accept-with-rationale**: the adapter is a forwarding seam (DES-012). The *right* place to test boundary handling is the library boundary, not here. Re-testing the library's input validation under our seam would couple our tests to library internals and break the swap-cost story DES-012 exists to enforce. Recorded explicitly here so the absence isn't read as a gap.

The only adapter-internal boundary is the `str(e) or "Authentication failed"` fallback — covered by M11's killer.

## Hygiene note

REQ-005's existing `test_password_not_retained_on_adapter_instance` checks `vars(client)` for the password string. It does NOT catch M4 (email/password swap) — under M4, the library-side `_garmin.password` holds the email and `_garmin.email` holds the password; neither is a direct attribute of the adapter, so the iteration misses it. The happy-path `captured["called_with"]` assertion is what kills M4. This is fine — REQ-005 is about *adapter* retention, not about wrapped-library state — but worth recording so a future reader doesn't mistake REQ-005's coverage for "no password anywhere in the object graph."
